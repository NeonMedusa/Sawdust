# 自动化（参数曲线）— 设计与实施计划

> **状态：仅设计，未实现。** 本文是动手前的定稿记录（模型 / 编辑视图 / 求值 / 存档 / 与 MIDI 的关系）。
> 讨论过的关键结论：**只有一套数据（点 + 每段插值）**，逐格与包络只是**两种编辑视图**，
> 切换不做任何转换；真正的“曲线 → 网格值”只发生在**出口**（导出 MIDI / 交给外部）。
>
> 相关：`docs/note-lane.md`（现有力度/声像编辑轨）、`docs/plugin-hosting.md`（VST3 参数自动化未做）、
> `docs/scheduler-protocol.md`（按步调度——自动化求值要与它对齐坐标系；
> 其中 **§11 的 Pull 模型改造计划**会把 lane 求值并入同一个“音频线程按时间取快照”的骨架）。

## 一、术语（先把名字定下来，避免各说各话）

| 概念 | 本文用词 | 说明 |
| --- | --- | --- |
| 断点 + 每段插值/曲率 | **包络自动化**（envelope automation） | 主流 DAW 普遍都有：自动化片段 + 曲线工具 |
| 每格一个值、格间阶跃 | **步进自动化**（step automation） | 精度 = 网格（本工程 1 格 = 1/96 全音符） |
| 挂在音符上的值 | **音符属性**（note property） | 力度、音符声像——**不是**自动化（没有独立时间轴） |
| 两点之间的弯曲参数 | **曲率 / 张力**（curvature / tension） | ⚠️ 不要叫 “Q”——Q 专指滤波器品质因数 |

**MIDI 的事实**：协议里只有 tick 上的离散事件（CC / 弯音 / 触后），**没有曲线**。
DAW 的包络是编辑层抽象，到出口一律冻结成离散事件；**VST3 例外**——参数走
`IParamValueQueue`，可以逐采样送达（本工程 `vst_host.zig` 已有 `ParamValueQueue`）。

## 二、数据模型（唯一权威）

```zig
const Point = struct {
    step: i32,            // 与音符/片段同一坐标系（U = 96/全音符）
    value: f32,           // 目标参数的归一化值（或原始值，见“目标定义”）
    curve: f32 = 0,       // 段曲率：-1..1（仅 smooth 有意义；0 = 线性）
};

const Lane = struct {
    target: Target,       // 见 §七（通道推子 / CC / BPM / …）
    interp: enum { hold, linear, smooth },
    points: ArrayList(Point),   // step 升序，≥ 1 点
    smoothing: f32 = 0,   // 播放侧一极点平滑（0 = 关；hold 模式建议开）
};
```

**四条铁律**

1. **只有这一套数据**：不存在“两种模式两套数据”，也就没有双向同步（两份真相 = 分叉 bug 的温床）。
2. **`hold` 段 ≡ “每格一个值”的数组**（数学上等价，不丢精度）——逐格模式就是一堆 `hold` 段。
3. **等值段自动合并**：相邻同值 + `hold` 合并为 2 个点（否则一次“画 16 小节恒定值”会生成上千点）。
4. **空 lane = 没自动化**：参数用 UI 上的静态值；空 lane 不写进存档。

## 三、两种编辑视图（切换零转换）

| 视图 | 用户看到 | 手势 → 底层动作 |
| --- | --- | --- |
| **柱条（逐格）** | 每格一根柱 / 一段台阶 | 拖一格 = 在该格边界放 `hold` 点，并与相邻等值段合并 |
| **包络** | 折线 + 可拖点 + 曲率手柄 | 双击线上加点、拖点、拖手柄调 `curve`、右键删点 |

- 切换**只换绘制与手势**，数据一个字节都不动；柱条视图在曲线段上显示“按格采样后的值”（预览，不改数据）。
- **混合编辑策略（默认 a）**：lane 里已有曲线段时，在柱条视图拖某一格 = 在该格前后插点、只把这一小段变 `hold`
  （“曲线里挖出一个台阶”），其他段不动。整条 lane 烘焙成逐格 = 独立命令（需确认、可撤销），**不做默认**。

## 四、求值（音频线程）

- 每 block 取首/尾 step → 定位所在段 → 按 `interp` 求值（`hold` = 段起点值；`linear` = 线性；`smooth` = 按 `curve` 造型）。
- 求值结果统一过**一极点平滑**（可复用 `audio.zig` 里音频片段增益的平滑代码），`smoothing = 0` 时不平滑（想要硬台阶的用户自选）。
- 参数投递路径：
  - 内置参数：写原子数组（`params.*`，已有机制）；
  - VSTi 参数：`IParamValueQueue`（可逐采样）或 CC 事件——两者都要“最后写入者胜”；
  - 事件型目标（如弯音/CC 给外部 MIDI）：走现有事件队列（`SchedEvent` 已有 `step`/`end_step` 语义，需扩一个参数事件类型）。
- **待定**：点数组的跨线程发布方式（双缓冲 + 版本号 vs 发布指针 + 原子序号）——先按“UI 线程构造新数组、音频线程按版本切换”设计。

## 五、存储与历史（字段纪律，一步都不能漏）

新字段必须一次改全**五处**，否则就是 `instrument_order` 那个坑的重演（改了不进历史 / 不标脏 / 撤销丢数据）：

1. `persist`：`automation: []SavedLane`，`binary_version` +1，`introducedVersion` 用固定版本号；
2. `captureHistory`：深拷贝 lane 点集；
3. `stateEqualsCurrent`：**比较 lane 内容**（否则改自动化不产生历史、不标脏）；
4. `applyHistoryState`：恢复（含 lane 数量/顺序，非法数据回落空）；
5. `freeHistoryState`：释放（否则每次提交泄漏）。

## 六、与 MIDI 的关系（烘焙只在出口）

- **导出**：lane → CC 事件，按 tick 采样；`interp = hold` 时只在“值变化处”发事件（事件数最省）。
  弯音 → Pitch Bend（14 bit）；通道声像 → CC10。
- **导入**：CC 事件 → lane（每个事件一点 + `hold`），round-trip 只保证“采样点一致”，不保证曲线形状。
- **内部永不量化**：量化只发生在这两个出口。

## 七、目标定义（target）与归属

`target` 必须是**稳定 id**（不是名字），否则改名/重载插件后 lane 对不上：

| 类别 | 示例 | 归属（lane 挂在谁身上） |
| --- | --- | --- |
| 全局 | 主音量、**BPM**、拍号 | 工程（单条） |
| 调音台通道 | 通道音量 / 声像 / 静音、效果器参数 | **通道**（不是轨道行！一个通道可能被多个乐器/轨道使用） |
| 乐器 / MIDI 通道 | CC 0–127、弯音、触后 | 乐器（本工程约定：一个乐器 ≈ 一个 MIDI 通道） |
| VSTi 参数 | 插件参数 id | 插件实例 + 参数 id |
| 音符属性 | 力度、音符声像 | 音符（**不是 lane**，保持现状） |

### 7.1 视图分工：两个编辑区，作用域互不交叉

| 编辑区 | 位置 | 可编辑的 target |
| --- | --- | --- |
| **钢琴窗下方编辑区**（由现有 `view_note_lane.zig` 改造） | 卷帘底部 | **乐器 / MIDI 通道级**：音符属性（力度、音符声像）+ 该乐器的 CC / 弯音 / 触后 |
| **播放列表自动化区**（新增，同款 UI） | 播放列表轨道区下方 | **全局 / 调音台级**：`通道 A · 音量`、`通道 A · 声像`、主音量、**BPM** 等 |

理由：

- 卷帘里能看到“音符与曲线的**时间对齐**”，所以乐器级的东西在卷帘里画；“这条自动化覆盖了哪几个片段”要在播放列表里才看得清，所以全局/调音台级的东西在播放列表里画。
- 两处**共用同一套 lane 渲染器与手势**（柱条/包络两个视图、加点拖点、值域映射、行高、颜色），但**数据源与 target 白名单不同**。
  实现上抽成“值轨控件”，输入 =（lane 列表, 值域, 颜色, 行高）。
- **不允许交叉**：卷帘里不能编「主音量」，播放列表里不能编某乐器的 CC。
  需要时用“跳转”而不是“复制”：参数旁的小圆点 → 跳到对应编辑区并高亮该 lane。

## 八、未决问题（下次讨论）

1. lane 出现在哪：钢琴卷帘（乐器/MIDI 通道类）与播放列表（全局/调音台类）各一套视图，还是统一？
2. 控件与自动化的冲突：lane 存在时，拖 UI 旋钮怎么办（只读 + 提示 / 写入播放头处的点 / 进入 write 模式）？
3. BPM 自动化与“按步调度 + 4 小节前瞻”的耦合（前瞻窗口内改 BPM 会改变已排程事件的实际时间）——是否只允许整小节变化？
4. 可复用的“自动化片段”（可拖进播放列表的自动化对象）：lane 升级为可放进播放列表的片段，何时做？
5. VSTi 参数与插件自身 UI 的写冲突策略（时间戳 / 之后写入胜）。

## 九、交互定稿（v0 原型）：值轨控件 + 曲率手柄

> 定稿决策：**对称曲率（每段一个标量）+ 手柄派生 + 每段 (interp, curve)**；
> 播放列表的自动化编辑区 = **轨道区下方的独立面板**（与钢琴窗底部那片同款外观，
> 两处共用同一套“值轨控件”，只是可编辑的 target 白名单不同，见 §7.1）。

### 9.1 曲率手柄的数学（**不是贝塞尔控制点**）

```zig
t = (step - p0.step) / (p1.step - p0.step)        // 0..1
v = lerp(p0.value, p1.value, t) + p0.curve * 4*t*(1-t)   // 抛物鼓包：中点峰值 = curve
```

- 端点鼓包为 0 → **线永远穿过锚点**；中点鼓包 = `curve` → **线正好穿过手柄**（拖上去上凸、拖下来下凹）；
- 反解一行：`curve = (鼠标值 − 中点线性插值) / 全量程` → 拖动 1:1 跟手；
- `curve` 存**归一化值**（相对参数全量程）→ 拖动锚点时段形状比例保持、与缩放无关；
- `interp = .hold` 的段**没有曲率**（手柄隐藏）。

### 9.2 存储与派生

- `points[]` **只有锚点**；曲率是**左锚点上的属性**，手柄是**派生**出来的（不占点、不参与命中排序）；
- `interp` 与 `curve` 都是**每段**属性（存在该段左锚点上）→ 一条 lane 可以“前两段直线 + 中间鼓包 + 末尾阶跃”。

### 9.3 v0 原型范围（**不进历史、不存档**，纯手感验证）

| 做 | 不做（正式版再做） |
| --- | --- |
| 播放列表下方固定高度面板（分隔线可拖高，默认 170px） | 多 lane 堆叠、钢琴窗 CC lane |
| 一条 lane：`通道 1 · 音量`（下拉可切 主音量 / 通道 2） | 多选、复制粘贴、框选 |
| 双击加点 / 拖锚点 / 右键删点 / 拖动手柄 / 双击手柄归零 / `Ctrl` 吸附 0 | 非对称曲线、平滑拐角 |
| 实时数值读数 + 每段的“直线参考线” | 吸附到其它 lane 的点 |
| **UI 线程每帧求值 → 写 `params.channel_gain[ch]`（听得见）** | 求值器下沉到音频线程 / 进快照 |

> 为什么 v0 让声音真的出来：包络手感有一半是听觉的（渐强是否自然、拖锚点声音跟不跟），
> 而成本极低 —— 通道增益本来就在每帧同步，UI 线程求值后覆盖即可，**音频线程一行不改**。

### 9.4 控件 API（`src/view_lane.zig`）

```zig
pub const Interp = enum { hold, linear, smooth };
pub const Point = struct { step: i32, value: f32, curve: f32 = 0 };
pub const Lane = struct { target, points, /* 手势态 */ … };
pub fn evalAt(lane, step) f32            // 段定位 + 鼓包求值（供 UI 每帧 & 将来音频线程共用）
pub fn insertPoint(lane, alloc, step, value) usize
pub fn removeAt(lane, idx) void
pub fn draw(ui, app, lane, x, y, w, h, step_px, first_step) void   // 渲染 + 手势（v0 全在这里）
```

钢琴窗将来的用法：同一控件、不同目标集（力度/声像 per-note → CC lane）——见 §7.1。

## 十、复用计划：一条「编辑区」两种内容

> 定稿方向（用户拍板）：**钢琴窗底部编辑区与播放列表底部自动化区是同一套东西**，
> 同一片网格、同一套轴/值映射/数值读数，只是**内容与操作逻辑**不同；
> 而且钢琴窗将来也要在同一片网格里切到「**乐器音量**（= MIDI 通道音量）」用**包络**方式画线
> （现有的音符级力度/声像**保留**）。

### 10.1 分层

```
lane_core（view_lane.zig 内）
  ├─ 几何/轴：xOf / stepOfX / yOf / valueOfY；竖线（小节/拍）与横向值参考线（grid_bar / grid_snap）
  ├─ 值读数、命中半径、hover 光标
  └─ Mode 分发：
      · .notes_velocity / .notes_pan   → per-note 柱条渲染 + 画笔/Alt+滚轮手势（现有 view_note_lane 的逻辑）
      · .lane_envelope                 → 锚点 + 曲率手柄 + 曲线渲染（§九）
```

- **数据源两种**：
  - `per_note(Velocity|Pan)`：值直接从 `notes[]` 读/写，**不额外存储**；
  - `envelope(target)`：`Lane{points}`（§二），存储/历史/求值走 lane 那条线。
- **选择器**：钢琴窗现在是 `toggle2`（力度/声像），播放列表是按钮循环切目标；
  将来统一成**可滚动的 lane 列表**（展开后一行一个可编辑项）。

### 10.2 「乐器音量」在钢琴窗里怎么放

- 目标 = `envelope(instrument_volume(inst_id))`，**与播放列表的「通道音量」是不同 target**：
  - 钢琴窗的是**乐器**作用域（导出 MIDI 时 = 该乐器通道的 CC7/音量）；
  - 播放列表的是**调音台通道**作用域（影响整条总线）。
- 同一片网格里切换模式时：per-note 模式显示音符柱条，envelope 模式显示锚点曲线 —— 两者**互不干扰**（不同数据源）。
- target 用**稳定 id**（`docs/automation.md` §七）：乐器/通道改名不影响已有 lane。

### 10.3 落地顺序（建议）

1. **抽 lane_core**：把 `view_note_lane.zig` 的几何/网格/值映射/读数搬进 `view_lane.zig`，
   `view_note_lane` 变成“per-note 渲染器”的实现体（行为不变，只换壳）；
2. `view_lane` 增加 `Mode` 与分发，钢琴窗/播放列表分别传自己的 mode 与数据源；
3. 钢琴窗加「乐器音量」模式（envelope）→ 先**只快照求值/UI 线程驱动**，验证手感；
4. 之后才进历史/存档（§五 五处同改）与音频线程求值（并入 `Snapshot.lanes`）。

### 10.4 v0 已知待修细节（用户反馈）

- 分隔条统一为 `ui.splitterH`（4px）✓ 已改；
- 横向值参考线用 `grid_bar` / `grid_snap` 两级、**只作视觉参考、不吸附** ✓ 已改；
- 竖线（小节/拍）参数与钢琴窗一致（`app.steps_per_bar`）✓。

## 十一、作用域划分：样式作用域 = MIDI CC，工程作用域 = 绝对自动化

> 起因：把「乐器音量/声像」画在钢琴窗里会撞上一个语义难题 —— 钢琴窗编辑的是**样式**，
> 而一个样式可以在播放列表里放**多个片段实例**；两个实例时间重合时，同一个乐器、同一时刻出现两个值。

### 11.1 两种自动化，两种语义

| | **样式作用域**（钢琴窗） | **工程作用域**（播放列表） |
| --- | --- | --- |
| 挂在谁身上 | 乐器 + **CC 号**（`pattern_cc[instrument][cc]`） | 目标（乐器/调音台通道/主音量/BPM） |
| 时间轴 | **样式内局部时间**（跟着片段窗口裁剪/循环） | 全曲**绝对**时间 |
| 语义 | **MIDI CC 事件流**：某一步把该通道的该 CC 设成某值 | 参数随时间的绝对曲线 |
| 重叠 | 时间合并，**后到的实例生效**（与音符同规则） | 不存在重叠（一目标一条） |
| 命名 | **`CC7 · 通道音量` / `CC10 · 通道声像`** | `乐器音量` / `通道 A · 音量` … |
| MIDI 导出 | 天然对应 CC 事件（逐实例展开、按时间合并） | 混音设置（不导出为 CC）/ BPM 导出为 tempo |

**为什么钢琴窗里用 CC 语义**：样式里的东西本来就是“事件”，和音符同一类；重叠时按时间合并，
不需要发明新规则 —— `topmostClipAt` 那套「后开始者优先（同起点取数组序大）」的层级判据可直接复用。

### 11.2 能不能让**片段实例之间完全隔离**（各算各的增益）？

技术上**可以**，但代价不小，且与主流 DAW 的直觉相反：

- 现状：`params.instrument_gain[i]` 是**每乐器一个绝对值**，在 `renderSegment` 里乘到整条乐器输出上；
- 要隔离 → 增益必须下沉到**声部级**：`Voice` 加 `gain`，并且声部要记住“我来自哪个片段实例”，
  然后**每块**按该实例的曲线求值再乘（因为音可能比片段尾部活得更久）；
- 牵连：`Scheduler`/快照要带“片段实例 id”，`reconcileVoices` 的对账键也要加它，
  `sched_stress` 与对拍测试都要扩；工作量大致 = 一次中型改造（比重扫治理小，但比本轮的 CC 大步子大）。
- 收益：重叠时两边的自动化**互不影响**（各乘各的），确实更“干净”。

**但主流 DAW 都不这么做**：

| DAW | 情况 |
| --- | --- |
| 多数线性 DAW | MIDI CC（含 7/10）是**事件流**，按时间合并；同一轨道**不允许两个 part/clip 同时播放** → 重叠问题天然不存在 |
| 片段式 DAW（非线性格栅） | 同一轨道**允许**重叠；层级判据 = 上面的盖住下面的（等价于“后开始者生效”） |
| 普遍规律 | **通道级参数（音量/声像）的“混音式”自动化一律放在工程/轨道层**，不放在 pattern 里 |

→ 结论：**先用 CC 事件流（后到者生效）**，把“实例级隔离”作为将来可选项（等真觉得需要再上，
它属于“增益下沉到声部”那一档改造）。

### 11.3 迁移步骤（当前进度）

## 十二、备选架构设想（**记录待斟酌，不实现**）

> 用户提出的另一种形态：**砍掉“音符样式 / 音符片段”这套两层模型**，改成单层三栏：

```
钢琴窗（直接编辑音符，不再有 pattern 概念）
自动化编辑区
音频轨道（音频片段）
```

- 好处：没有“样式实例”这层间接 → **样式作用域 vs 工程作用域的分裂自然消失**（一切都变成“轨道上的东西”）；

  音频片段与 MIDI 轨道需要统一的时间轴/裁切语义。
- 结论：**先不动**。等自动化（尤其 CC 与混音自动化）落地后，回头评估“样式是否真的还值这个复杂度”。

### 11.6 坐标单位铁律（本轮两个 bug 的教训）

两个 bug 都出在**同一个地方**：“屏幕坐标”与“内容坐标”混用。

1. **`drawShell` 的网格与游标**：`util.drawTimelineGrid` 要的是**内容**量（`step_w` 未乘 zoom、`scroll_x` 内容像素、`zoom` 单独传），我一开始把**已乘 zoom 的屏幕滚动**当内容传 → 曲线/网格在缩放时各走各的。现在 `Shell` 只收内容坐标（`step_w` / `scroll_x` / `zoom`），屏幕量在 `drawShell` 内部算。
2. **`view_lane.draw` 的 `first_step`**：它是**步号**，不是像素；调用方曾把 `scroll_x`（像素）当步号传 → 静止时（scroll=0）完全看不出来，一缩放就错位。现在**签名里干脆删掉** `first_step`，改由 `scroll_x ÷ step_px` 在 `view_lane.draw` 内部唯一一处换算。
3. **游标**：钢琴窗编辑区原来**只有柱条分支**画游标，切到 envelope 分支就没了 → 游标收进 `drawShell`（`cursor_step`），由调用方按 SONG/PAT 规则算出“是否在片段内”，两分支都有。

### 11.7 最终模型拍板（曲线是主角，参数是订阅者）

用户定稿：**一条曲线可以被多个旋钮/推子/CC 共享**。于是模型不是“参数 → 曲线”，而是

```
Curve   { id, scope, pat, name[24], points, interp, curve, display_kind }
Binding { curve_id, target }        // 多对一：一个目标至多绑一条曲线，一条曲线可绑多个目标
Target  { kind, idx }               // .cc(号) .mixer_vol(ch) .mixer_pan(ch) .master_vol .tempo
```

四条铁律：

1. **作用域在曲线上**（`.pattern` 跟片段/局部步；`.project` 绝对步），**绑定只能同作用域**——否则同一条曲线要在两个时间轴上求值。
2. **曲线内部存归一化 0..1**，各目标自带量程（CC ×127；音量 ×1；声像 ×2−1；**BPM 20+979v**）。显示单位取 `display_kind`（创建时第一个绑定目标）。
3. **绑定用稳定 `id`**（单调递增、不复用），不用下标；删曲线时若绑定数 > 1 → 二次确认。
4. **“后到者生效”只在两条不同曲线绑同一目标时裁决**：排序键 `(start_step, 绑定创建顺序)`，永久确定。

### 11.8 UI 定稿（**最新：钢琴窗只做音符级，曲线全归播放列表**）

#### 两个窗口的分工（**已定稿**）

| 窗口 | 提供什么 | 不提供什么 |
| --- | --- | --- |
| **钢琴窗底部编辑区** | **只有音符级柱条**：`音符力度` / `音符声像`（每个音符一个值，本质离散，不需要画曲线） | **没有** MIDI CC lane、**没有** envelope 曲线视图、**没有** `+ MIDI CC` 按钮 |

#### 播放列表自动化区的入口

| 统一菜单 | `创建自动化曲线`（新建 + 自动命名 + 绑定）/ `链接到曲线 ▸`（列出同作用域曲线 + 各自绑定数）/ `取消链接`（曲线保留，只是该参数不再被驱动） |
| 行头列 lane 行 | **右键** → `重命名` / `删除曲线` / `取消此绑定` |
| 行头列空状态 | 面板内提示：`右键混音台推子/旋钮 → 创建自动化曲线` |

#### 已删除 / 不做的项

### 11.10 显示单位（用户拍板：**两行**）

一条曲线可绑多个异构目标 → “用谁的单位”由**曲线自己**回答：

- `Curve.display_unit ∈ {percent, midi, db, bpm, pan}`，**存储永远是归一化 0..1**，单位只管显示与键入；
- 行头列**第 1 行 = 单位按钮**（点击循环）、**第 2 行 = 数值**（点击 → 复用 `app.rename`/`text_edit.zig` 的输入框键入）；
- 循环集合按**已绑定目标的种类过滤**（`unitCycle`）：声像类 → `%/MIDI/PAN`，其余 → `%/MIDI/dB`，BPM 曲线将来加 `BPM`；
- 映射（`formatValue` / `parseValue`，已有单测 `unit: 归一化 ↔ 显示 往返稳定`）：
  | 单位 | 显示 | 键入 |
  | --- | --- | --- |
  | `%` | 0–100 | `/100` |
  | `MIDI` | 0–127 | `/127` |
  | `dB` | `20·log10 v`（钳 −60..+6） | `10^(db/20)`；**≤ −60 → 0（静音）** |
  | `BPM` | 20–999 | `(x−20)/979` |
  | `PAN` | `L100 – C – R100` | `±x`/`C` |
- 读数优先级：**拖动 > 选中 > 悬停 > `—`**（两个编辑区同格式）；**选中点画外环**、`sel_idx` 越界自动失效。
- 顶部读数**不显示目标名**（列表行已经写着），只显示数值；曲率手柄显示 `曲率 ±NN%`。

### 11.11 选中点（`sel_idx`）

- **左键点锚点 = 选中**（`Lane.sel_idx`），鼠标移开不丢 → 行头列第 2 行持续显示它的值；
- 选中点画**外环**（accent 描边）＝“这个点能键入数值”；拖动中同样高亮；
- 点空白 → 取消选中；点被删除/越界 → 自动失效；
- 与拖动共存：拖动时读数跟拖动点（`drag_idx`），松手后落在 `sel_idx` 上。

### 11.12 键入数值（行头列第 2 行）

链路：**点锚点选中** → **点第 2 行的数值** → 弹出输入框（复用 `app.text_input` 全套：IME / 选区 / 光标 / Ctrl+A / Esc 取消）→ 回车提交。

| 项 | 实现 |
| --- | --- |
| 输入框种类 | `TextInput.Target.automation_value`（新变体） |
| 目标 lane | `TextInput.auto_lane: i16`：`>= 0` = `app.env_lanes[i]`（钢琴窗），`-1` = `app.auto_lane`（播放列表） |
| 目标点 | `TextInput.index` = 点下标（= `Lane.sel_idx`） |
| 预填 | 当前值**按当前显示单位**格式化后全选（直接输入即替换） |
| 解析 | `view_lane.parseValue(lane.display_unit, text)`；失败 → **保持不变**；成功 → 钳制 0..1 写回 |
| 历史 | **暂不提交**（曲线尚未进历史，S5）——否则会快照“不含曲线”的状态导致撤销不一致 |
| 单测 | `automation_value: 键入数值按显示单位解析（% / dB 静音 / 非法输入）` |

**为什么必须“先选中”**：输入需要一个稳定的目标点（鼠标移开不能丢）。所以第 2 行的可点区域只在 `sel_idx != null` 时生效，悬停会提亮作为提示。

### 11.13 单点曲线的显示

`points.len == 1` 时画一条**穿过该点的水平线**（accent）——几何上它就是“常量”，
否则用户在格子上看不到这个值作用于哪里。两点以上由正常曲线绘制接管。

### 11.14 值轴映射与横向网格（“网格中线比曲线中线高几像素”）

**现象**：包络视图里，50% 的点躺在一条亮线上，但它背后还有一条网格线，比它**高出几像素**；同时力度柱条看起来“悬空”。

**根因有两个**（都不是绘图误差，是**两套定义**）：

1. **“中线”被画了两次、而且不是同一条**：
   - 8/32 参考线是按 **MIDI CC 值 0..127 的 8 的倍数** 画的 → 那条“中间”的线是 `vv = 64` = **50.394%**；
   - 另外又单独画了一条 **正好 50%** 的 `grid_bar` 线。
   → 面板越高差得越多（可用高 700px 时约 **2.8px**），于是 50% 的点（走真正的 0.5 映射）与 `vv=64` 那条线对不上。
2. **值轴上下各内缩 4px**（`inset = 4`）：0% 到不了底边、100% 到不了顶边 → 柱条/曲线整体“悬空”4px，且 50% 不在几何中心。

**修法**：

- **值轴不内缩**（`view_lane.yOf/valueOfY` 与 `view_note_lane` 的 `inset` 全部 → 0）：`0 → 底边`、`1 → 顶边`、`0.5 → 正中心`；
- **横向参考线改成 1/8 等分**（12.5%…87.5%），`k==4` 画中线（`grid_bar`，**只此一条**）、`k==2/6` 画 `grid_beat`、其余 `grid_snap`（太矮时只画 2/4/6）；
- **唯一实现** `view_lane.drawValueGrid(ui, Rect, dense)` —— 钢琴窗（柱条 + 包络两种模式）与播放列表**三处共用**，不可能再各自漂移；
- 力度柱条随之内缩归零 → 底边贴齐面板底边。

> 教训入 `docs/pitfalls.md`：**同一根轴线只能有一个“中间”的定义**；凡是“按离散刻度画线 + 另画一条几何中线”的写法，迟早会在某个高度上分叉。

### 11.15 横向对齐（点落不到竖网格线上）

**现象**：点按 1/96 步移动，但常常不在竖网格线上，且偏移量随缩放变化。

**根因**：滚动量被**截断成整步**后再乘步宽：

```zig
// 旧（错）
first_step = trunc(scroll_x / step_px)          // 丢掉不足一步的余量
px = x + trunc((step - first_step) * step_px * zoom)
```

网格那边用的是**精确屏幕滚动** `scroll_s = scroll_x * zoom`，于是两者最多差**一个步宽**，且差值随 `zoom` 放大。

**修法**：`xOf` / `stepOfX` / `curveHandlePos` 全部改用 `scroll_s`，表达式与 `drawTimelineGrid` **逐字符同式**：

```zig
px = x + trunc(step * step_px * zoom - scroll_s)   // 与网格 gx 完全一致
stepOfX = round((px - x + scroll_s) / (step_px * zoom))   // 取最近步 → 拖动自然吸附
```

曲率手柄的 x 也从“整数步中点”改成“两个锚点的**屏幕中点**”（前者会被截断，手柄偏离段中点）。

**回归测试**：`lane: 锚点 x 与竖向网格线逐像素重合（任意缩放/滚动）` —— 5 种缩放 × 5 种滚动 × 400 步，逐像素断言 + 反解回步号。

### 11.16 拖动抓取偏移（消除“按下即微跳”）

**现象**：光标在锚点附近变成 ↕ 后按下左键，点会**轻微瞬移**到鼠标正下方——其实只想单击选中。

**根因**：拖动逻辑每帧直接把点设成 `valueOfY(mouse)`，按下的那一帧就对齐了鼠标（哪怕是 1px 的误差）。

**修法：抓取偏移**（用户建议的方案二，等价于“按移动量拖动”）：

```zig
// 按下瞬间
grab_step  = point.step  - stepOfX(mouse_x)
grab_value = point.value - valueOfY(mouse_y)
// 拖动中
point.value = clamp(valueOfY(mouse_y) + grab_value, 0, 1)
point.step  = max(0, stepOfX(mouse_x) + grab_step)
```

- 按下但不移动 → 点**一动不动**（偏移量保持不变）；
- 曲率手柄同样记偏移（`mid_v - valueOfY(mouse)`），否则按下时曲线会“跳一下”；
- 偏移量存在 `Lane.grab_step / grab_value`（每帧重算绝对位置，不会累积漂移）。

### 11.17 光标与悬停提示（定稿：**不改鼠标形状**）

用户拍板：**鼠标光标始终保持系统默认箭头**，可操作提示由**控件自身高亮**承担：

| 状态 | 锚点 | 曲率手柄 |
| --- | --- | --- |
| 悬停 | **蓝色外环**（与选中环同款，方块保持白） | 菱形变 accent |
| 选中 | 外环 + **方块变 accent** | — |
| 拖动中 | 外环 + 方块 accent | 菱形 accent |

好处：不再需要“拖动期光标由状态决定”那套代码（鼠标甩快/移出网格区都不会有光标退化问题），
也就不必为拖动专门隐藏光标（隐藏光标在 Win32/X11 上机制不同，见 §11.18）。**这个设计顺便绕开了平台差异。**

### 11.18 附：隐藏光标在两平台上的现状（仅备查，未采用）

| | Win32 (`window.zig`) | X11 (`window_x11.zig`) |
| --- | --- | --- |

### 11.19 拖到面板外到不了 100%（夹紧时机错了）

**现象**：抓着点往上一路拖出面板，值常常停在 97/98/99%；如果按下时鼠标在点中心**偏下**一点，就能到 100%。

**根因**：`valueOfY` 自带 `clamp(0,1)`，而拖动是“鼠标值 + 抓取偏移”：

```zig
grab_value = point.value − valueOfY(press_y)     // 按下时鼠标偏上 → 负值
p.value = clamp(clamp(valueOfY(mouse_y)) + grab_value)
                └── 已夹到 1.0 ──┘  └─ 再减 |grab_value| → 永远 < 1.0
```

**修法**：拖动用**不夹紧**的反解 `valueOfYRaw`（`1 − (mouse_y − y)/h`），最后只夹**一次**：

```zig
p.value = clamp(valueOfYRaw(mouse_y) + grab_value, 0, 1)
p.curve = clamp(valueOfYRaw(mouse_y) + grab_value − mid_lin, −1, 1)
```

夹紧（`valueOfY`）保留给“双击空白加点”——那里确实需要落进 0..1。

**单测**：`lane: 拖动到面板外可达 0% / 100%`（构造负偏移，断言旧写法 <1、新写法 ==1；反向验 0）。

### 11.20 定稿：钢琴窗只做音符级；曲线归播放列表；绘制连续

**用户拍板（本轮）**：

1. **钢琴窗的 MIDI CC lane 全部删除** —— 钢琴窗只剩「音符力度 / 音符声像」两种**柱条**视图（音符级属性，本质离散）。
   理由：音符级的力度/声像天然是“每个音符一个值”，不需要画曲线；而**连续曲线**（BPM、通道/乐器音量声像）全部归**播放列表的自动化区**（工程作用域、绝对时间轴）。
2. **白线（锚点直连参考线）删除** —— 它在 `curve ≠ 0` 与 `hold` 段与真值不符（用户实测混淆“白线还是蓝线是真的”）。
3. **`evalAt(step: f32)` 连续求值** —— 锚点仍存整数步（吸附网格），但段内任意位置可取値；绘制逐像素取**小数步**（`stepOfXf`）→ 曲线平滑，不再有 1/96 台阶。

**连带简化**：

| 删掉 | 说明 |
| --- | --- |
| `app.env_lanes[5]` / `env_target` / `piano.lane_env` | 钢琴窗 envelope 分支整个消失 |
| `app.applyEnvLanes()` | 乐器增益/声像的 UI 线程求值随之删除；`applyAutoLane()` 保留（通道作用域） |
| 钢琴窗 `+ MIDI CC` 设想 | 不做（若将来要 CC，也只能在播放列表侧） |
| §11.3「CC 按片段实例求值 / 后到者生效」 | **决定不做**（没有 pattern 作用域的 CC 了，无重叠歧义） |

**求值精度分层（定稿）**：

| 层 | 粒度 |
| --- | --- |
| 锚点落点（编辑） | 整数步 = 1/96 全音符（吸附） |
| 曲线绘制 | **逐像素 + 小数步**（连续） |
| 音频应用（现状） | UI 帧一次（≈60Hz）→ **待改**：音频线程每块 + 块内斜坡（下一步） |
| MIDI 导出（将来） | tick（PPQ）+ 值 7-bit，只在出口烘焙 |

### 11.21 音频侧求值（A：音频线程求值 + 块内斜坡）——已落地

**去掉了**每帧写通道增益的 `applyAutoLane()`，改成**无锁发布 + 音频线程求值**：

| 环节 | 实现 |
| --- | --- |
| UI 线程 | `App.publishAutoLane()`：把 `auto_lane` 拷进 `Params.lane_bufs[next]`（**3 缓冲轮转**），写完 `lane_pub.store(next, .release)`；每帧调用一次（≤64 点 ≈ 0.8 KB，代价可忽略） |
| 音频线程 | `renderSegment` 开头 `lane_pub.load(.acquire)` 读一次；用**段坐标**算段首/段末的小数步（与音频片段那套映射同式），取 `evalAt(st0)/evalAt(st1)` 两个端点 |
| 增益应用 | 端点值相同 → **走原来的常量增益循环**（零额外开销）；不同 → **逐采样线性斜坡**（消除 16 ms 阶梯 / zipper） |
| 语义 | 曲线存在时**覆盖**该通道静态推子（与之前一致）；无点或 CC 目标 → 不 active，回落推子 |
| 诊断 | `[sched] 1s: … | lane 斜坡={d}` —— 每秒汇总做过斜坡的通道数 |
| 对拍 | 单测 `LaneSnap（音频侧副本）与 view_lane.evalAt 逐点一致`：hold/linear/smooth × 300 个采样点，误差 < 1e-6 |

**代价**（估算，真机看 `[sched]`）：每段 2 次 `evalAt`（≤64 点线性扫）≈ 0.3 µs；48 kHz/256 帧时占块预算（5.3 ms）**≈ 0.006%**。

**顺带解决的**：UI 卡住（拖窗/开菜单）时自动化**不再冻结**——求值在音频线程，与 UI 帧率解耦。

### 11.26 新设计设想：**“自动化”链接窗口**（一参数可挂多条曲线）

> 用户提出（2026-11-07）：把右键菜单里的「创建 / 链接到 / 取消链接」三项**统一成一个 `自动化…`**，
> 点开一个**专门设置链接的窗口**；窗口里将来还可以给每条链接画**映射曲线**（左下→右上 = 1:1，
> 左上→右下 = 反向）。**映射曲线本轮不做，只留占位。**

#### 为什么这个方向更强

| | 现在（多参数 → 1 曲线） | 新设想（1 参数 ↔ 多曲线） |
| --- | --- | --- |
| 混音技巧 | 一条包络同时推两个推子 | **同一个推子被多条包络叠加**（一条做整体渐强、一条做呼吸感） |
| 数据结构 | `Binding{curve_id, target}` | 同一张表，但**按参数反查**是常态 → 天然支持多行 |
| UI 入口 | 三条菜单项 | **一条 `自动化…`**，其余全在窗口里 |

#### 窗口布局（v1 设计稿）

```
┌ 自动化 · 通道3 · 音量 ────────────────────────────────── ✕ ┐
│ 当前值  0.62 (≈ -4.2 dB)   ▍基础值来自推子 0.80            │ ← 顶部状态行（只读）
├───────────────────────────────────────────────────────────┤
│ [✓]  渐强包络           深度 ▁▂▃▄▅▆▇█ 100%  极性 单向  ▣  ×│ ← 链接行（可多条）
│ [✓]  呼吸（LFO 手画）    深度 ▁▂▃▄▅▆▇█  35%  极性 双向  ▣  ×│
│ [ ]  备用包络           深度 ▁▂▃▄▅▆▇█  50%  极性 单向  ▢  ×│ ← 未启用行变暗
├───────────────────────────────────────────────────────────┤
│ [+ 链接曲线 ▾]   [ 映射曲线…（占位）]                        │ ← 底部操作
└───────────────────────────────────────────────────────────┘
```

**链接行 = 一行六个元素**（从左到右）：

| 元素 | 交互 |
| --- | --- |
| `[✓]` 启用开关 | 关闭 = 该曲线不参与求值（行变暗，数值灰） |
| 曲线名 | 点击 → 跳到播放列表的该曲线（选中并滚动到它） |
| 深度滑条 | 0–100%（未来可允许 >100% 做夸张效果） |
| 极性 `单向/双向` | 单向 = 0..1 正向叠加；**双向 = −1..+1**（以 0.5 为中心做减法） |
| `▣` 映射缩略图 | 28×28 小方块：v1 **画一条 1:1 斜线**（占位），点击 → `映射曲线…`（本轮弹提示“暂未实现”） |
| `×` | 移除这条链接（曲线本身保留） |

**底部**：
- `+ 链接曲线 ▾` → 下拉：列出所有**未被本参数链接**的曲线 + 末项 `新建曲线…`（新曲线默认空点，自动加入行头列）；
- `映射曲线…` → 本轮**置灰**（占位），hover 提示“即将支持：为这条链接画映射曲线”。

**空状态**：`尚未链接任何曲线` + 一个醒目的 `+ 链接曲线` 按钮。

#### 求值规则（v1 建议）

```
参数值 = clamp( 基础值 + Σ_i ( 深度_i × 映射_i( curve_i(t) ) × (极性_i ? 2 : 1) − (极性_i ? 1 : 0) ), 0, 1 )
```

- **基础值** = 推子/旋钮的静态值（**不再被曲线“覆盖”**，而是“被叠加”）——这比现在的覆盖语义更符合直觉；
- 单向：`curve` 直接叠加；双向：把 `0..1` 展成 `−1..+1` 再叠加（适合“呼吸”“颤音”这类）；
- 所有叠加在**归一化域**做，最后钳到 `0..1`；
- ⚠️ 音量的“叠加域”有讲究：归一化域相加 ≈ 幅度相加（响度不线性）；**dB 域相加**更符合听感。v1 先用归一化域（简单），把“域选择”记成后续议题。

#### 数据模型增量

```zig
Binding {
    curve_id: u32,
    target:   Target,
    depth:    f32  = 1.0,   // 0..1（将来可 >1）
    bipolar:  bool = false,
    enabled:  bool = true,
    // 将来：mapping: MappingCurve（一串映射点；空 = 1:1）
}
```

→ 与现有 `Binding{curve_id, target}` **兼容扩展**（加字段即可），发布路径仍是“按通道展开”，
只是每条通道的 lane 数会 >1（`LaneSet.lanes` 从 4 扩到 8），且音频侧改为**求和**而不是覆盖。

#### 与“按曲线看”的视图一致性

同一个 `Binding` 表有**两个视角**，必须互相同步（删任一视角都要能反映另一侧）：

| 视角 | 位置 | 用途 |
| --- | --- | --- |
| 按**曲线** | 播放列表行头列 | 管理“这条曲线长什么样 / 删曲线” |
| 按**参数** | 本窗口 | 管理“这个参数挂了哪些曲线、深度多少” |

#### 分期

| 期 | 内容 |
| --- | --- |
| **v1** | 窗口外壳 + 行（启用/名字/深度/极性/移除）+ `+ 链接曲线` 下拉 + 空状态；映射缩略图只画 1:1 斜线；求值 = 基础值 + Σ（归一化域）；音频侧 `LaneSet` 扩容 + 求和 |
| **v2** | 映射曲线编辑器（点/曲线，含反向、S 曲线预设）；映射缩略图实时反映 |
| **v3** | 深度可 >100%、按目标类型选“叠加域”（dB/归一化）、LFO 型曲线（循环/相位） |

#### 待确认

1. **叠加语义**：`基础值 + Σ` （推荐）还是**相乘**（`基础值 × Π`，更像“调制深度”）？
2. **默认极性**：新链接默认 `单向` 还是 `双向`？（我倾向单向；双向留给用户手动开）
3. **窗口性质**：**浮动模态窗**（推荐，和机架/调音台窗口同款，可拖动、✕ 关闭）还是**就地弹出面板**？
4. **一个参数同时被多条曲线驱动时**，播放列表行头列是否要在行尾显示“×N”（表示被 N 个参数引用）？
### 11.27 自动化链接窗口（v1 已实现）

**入口**：混音台**通道条右键**（含主通道）→ 菜单末项 `自动化…`（已链接时显示 `自动化…（已链接）`）→ 打开浮窗。

**窗口**（`src/view_auto_win.zig`，460×268，可拖标题栏、`x` 关闭、点击窗外关闭、Esc 关闭）：

```
┌ 自动化 · 通道3 · 音量 ───────────────────────────── ✕ ┐
│ 基准 0.80  →  合成 0.62                                │  ← 状态行（按当前游标实时合成）
├───────────────────────────────────────────────────────┤
│ [✓]  曲线1   ▁▂▃▄▅▆▇█ 100%   [单向]   ▣ 1:1        ×  │  ← 每个绑定一行
│ [ ]  曲线2   ▁▂▃▄▅▆▇█  35%   [双向]   ▣ 1:1        ×  │
├───────────────────────────────────────────────────────┤
│ [+ 新曲线并链接]  [曲线3] [曲线4]                       │  ← 未绑定曲线一键链接
└───────────────────────────────────────────────────────┘
```

| 控件 | 行为 |
| --- | --- |
| `[✓]` | 启用/禁用该绑定（禁用 = 不参与合成） |
| 曲线名 | 点击 → 播放列表切到编辑这条曲线 |
| 深度滑条 | 0–100%（内部 0..1） |
| `单向/双向` | 点切换（单向 = 曲线 0 处不变；双向 = 曲线 0.5 处不变，可上可下） |
| `▣` | **映射曲线占位**（画 1:1 斜线；点击提示“即将支持”） |
| `×` | 解绑（曲线本身保留） |
| `+ 新曲线并链接` | 新建曲线 + 立即绑定 |
| 未绑定曲线芯片 | 点一下即绑定到当前参数 |

**合成公式**（音频线程与 UI 状态行**同一套**）：

```
参数 = clamp(静态推子 + Σ_i 启用_i × 深度_i × (双向 ? 2v−1 : v), 0, 1)
```

**播放列表行头列**同步改成**曲线列表**（显示曲线名，点击切换正在编辑的曲线），与窗口共享同一张绑定表。

**测试**：`曲线仓库 + 绑定（多通道共享一条曲线，发布为多条 lane）`、`一参数叠两条曲线——深度/极性/启用/钳制`、`LaneSnap 与 view_lane.evalAt 逐点一致`。

**未做（下一轮）**：映射曲线编辑器；曲线重命名/删除（含多绑定模态确认）；声像自动化；多条曲线同时被同一通道引用时的 `LaneSet` 上限（当前每通道最多 4 条）。

### 11.32 曲线行右键菜单 + 命名格式 + **一次崩溃的根因**

#### 右键改为菜单（原来直接删，太危险）

行头列曲线行右键 → 菜单：`重命名` / `删除曲线`（用 `util.menuPanel`，跟随鼠标弹出、点外部收起）。
- 重命名 → 文本输入框；
- 删除曲线 → 0–1 个链接直接删 + toast；**≥2 个链接** → 模态确认（§11.31）。

双击 = 重命名（保留，快捷）。

#### 命名格式

`通道1 · 音量2`（去掉了 `(2)` 的括号，行头列只有 56px 宽，能省则省）。

#### ⚠️ 崩溃根因：**持有 `ArrayList` 元素指针跨过删除**

```
Segmentation fault at 0xffffffffffffffff
view_lane.zig:273 in draw  →  for (ps, 0..) |p, i|      ← ps（点数组）已失效
view_playlist.zig:1468 in draw  →  view_lane.draw(ui, cur_lane, …)
```

`view_playlist` 在函数中段先 `const cur_lane = app.autoCurve().?`（**拿到仓库元素的裸指针**），
随后同一帧里右键删除曲线 → `removeAutoCurve()` 做 `orderedRemove` + `deinit`（搬移 + 释放内存）→
**`cur_lane` 变成悬垂指针**，紧接着的 `view_lane.draw(cur_lane)` 就是 use-after-free。

**修法**：所有会修改曲线仓库/绑定表的交互（列表点击、右键菜单、模态确认）都在**使用指针之前**处理，
并在真正绘制/求值处**重新解析**指针（`const draw_lane = app.autoCurve() orelse return;`）。

**通用规矩（已写入 pitfalls）**：`ArrayList` 元素的指针**只能用在“不会再改动该表”的短区间内**；
跨过任何可能 `append/orderedRemove/deinit` 的调用，必须重新取。

### 11.35 右键菜单整顿 + 乐器旋钮 bug

#### bug 1：乐器音量旋钮右键无菜单、声像右键却改音量

`view_rack` 里音量旋钮的右键判定**用错了 x**：当时 `cx` 还是**声像旋钮**的坐标（`cx += knob + 6` 还没执行），
于是：
- 右键**声像**旋钮 → 命中“音量右键”分支 → 弹出音量菜单 → `恢复默认值` 改的是 **volume** ✗
- 右键**音量**旋钮 → 没有任何分支处理 → 无菜单 ✗

**修**：把音量旋钮的右键判定移到 `cx += knob + 6` **之后**（= 音量旋钮自己的 x）。

#### 菜单整顿（用户拍板：控件菜单与容器菜单分离）

| 右键位置 | 菜单项 |
| --- | --- |
| **通道条本体**（空白/名字） | `重命名` / `删除通道` / `上移` / `下移` |
| **音量推子** | `恢复默认值`(0.80) / `自动化…`（`MixerWindow.ctx_vol` + `drawVolCtxMenu`） |
| **声像旋钮** | `恢复默认值`(0.50) / `自动化…` |
| **乐器音量 / 声像旋钮**（机架） | `恢复默认值` / `自动化…`（共用一套，`RackState.ctx_vol/ctx_pan`） |

原则：**控件自己弹出“改这个值”的菜单；容器只弹出“管理这个对象”的菜单**——
避免“右键通道 → 改音量”这种让人意外的入口。
> **补丁（同日）**：两个菜单**同时弹出**的根因是 `ctx_*` 不是互斥的——
> 右键推子只清了 `ctx_channel/ctx_pan/ctx_effect`，**没清 `ctx_vol` 的反向**：
> 先右键推子（`ctx_vol` 开）→ 再右键通道本体（`ctx_channel` 开）→ 两个菜单一起画。
> 现在：**每个右键入口都清掉全部 `ctx_*` 再设自己那个**。
>
> 同时按用户建议简化地盘划分：**通道条右侧整块（推子 + 数值 + 右侧留白，纵向整行）
> 都是音量推子的地盘**，右键只弹音量菜单；通道菜单只剩左侧（静音/声像/名字/路由）区域。

### 11.36 基准值/极性改为**按参数类型的内建默认**（对齐 VST3）

#### VST3 里确实有这两个概念

| VST3 概念 | 位置 | 含义 |
| --- | --- | --- |
| **`defaultNormalizedValue`** | `Steinberg::Vst::ParameterInfo` | 每个参数的**默认归一化值**（0..1），`Parameter::getInfo()` 就能读到 |
| **`kIsBipolar`** | `ParameterInfo::flags` | 该参数**有中心位置**（官方典型例子就是 **pan**）——本质就是“极性/双向” |
| `stepCount` / `unit` | 同上 | `stepCount == 0` = 连续；`unit` 给 dB/% 等显示单位 |

（对照：VST2 没有 bipolar 标志；MIDI CC 更是既无默认值也无极性，pan 中心 = 64 只是惯例。）

所以我们的做法不是自创，而是**照 VST3 的模型**给每种目标类型定 `默认基准值 + 默认极性`：

| 目标类型 | 默认基准 | 默认极性 | 说明 |
| --- | --- | --- | --- |
| `master_vol / mixer_vol / inst_vol` | **0.0** | 单向 | 曲线 0..1 直接就是音量（画多大声就多大声） |
| `mixer_pan / inst_pan` | **0.5** | **双向** | 中心 = 不改变，上下摆动 |

实现：
- `view_lane.Target.defaultBase(kind)` / `defaultBipolar(kind)`（注释里点名对应 VST3 的两个字段）；
- `bindCurveTarget` 的 `bipolar` 取 `defaultBipolar(kind)`；
- `LaneSnap.base` 由发布侧写入 `defaultBase(kind)`，音频侧 `值 = clamp(基准 + Σ贡献)`，**有绑定就不再叠加在推子上**（推子只在“无绑定”时生效）；
- `autoValueFor` 与自动化窗口状态行同规则：有绑定 → 基准 = 类型默认（窗口显示 `基准 0.00（类型默认）`），无绑定 → `…（推子）`。

**好处**（用户原话“基准值跟随旋钮太难用”）：自动化一旦挂上，行为就是确定的——
音量曲线画到 30% 就是 30%，不会因为推子原来在 0.8 而变成 110% 撞上限。

### 11.37 基准值每绑定可编辑 + 右键恢复默认

| 控件 | 左键 | **右键** |
| --- | --- | --- |
| 行内 `基0.00`（新加的小框，48×16） | 打开输入框**键入**基准值（按 % 解析，0..1） | **恢复类型默认**（`base = null` → 音量 0 / 声像 0.5） |
| `单向 / 双向` | 切换 | **恢复默认极性**（`Target.defaultBipolar`） |

- `Binding.base: ?f32`（`null` = 用类型默认）；显示为 `基0.30`，颜色：手动设过 = 亮白、用默认 = 灰；
