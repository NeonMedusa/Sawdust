# 自动化（参数曲线）— 设计与实施计划

> **状态：仅设计，未实现。** 本文是动手前的定稿记录（模型 / 编辑视图 / 求值 / 存档 / 与 MIDI 的关系）。
> 讨论过的关键结论：**只有一套数据（点 + 每段插值）**，逐格与包络只是**两种编辑视图**，
> 切换不做任何转换；真正的“曲线 → 网格值”只发生在**出口**（导出 MIDI / 交给外部）。
>
> 相关：`docs/note-lane.md`（现有力度/声像编辑轨）、`docs/plugin-hosting.md`（VST3 参数自动化未做）、
> `docs/scheduler-protocol.md`（按步调度——自动化求值要与它对齐坐标系；
> 其中 **§11 的 Pull 模型改造计划**会把 lane 求值并入同一个“音频线程按时间取快照”的骨架）。

## 一、术语（先把名字定下来，避免各说各话）

| 概念 | 本文用词 | 说明 |
| --- | --- | --- |
| 断点 + 每段插值/曲率 | **包络自动化**（envelope automation） | FL 的 Automation Clip、Cubase 的 Curve 工具 |
| 每格一个值、格间阶跃 | **步进自动化**（step automation） | 精度 = 网格（本工程 1 格 = 1/96 全音符） |
| 挂在音符上的值 | **音符属性**（note property） | 力度、音符声像——**不是**自动化（没有独立时间轴） |
| 两点之间的弯曲参数 | **曲率 / 张力**（curvature / tension） | ⚠️ 不要叫 “Q”——Q 专指滤波器品质因数 |

**MIDI 的事实**：协议里只有 tick 上的离散事件（CC / 弯音 / 触后），**没有曲线**。
DAW 的包络是编辑层抽象，到出口一律冻结成离散事件；**VST3 例外**——参数走
`IParamValueQueue`，可以逐采样送达（本工程 `vst_host.zig` 已有 `ParamValueQueue`）。

## 二、数据模型（唯一权威）

```zig
const Point = struct {
    step: i32,            // 与音符/片段同一坐标系（U = 96/全音符）
    value: f32,           // 目标参数的归一化值（或原始值，见“目标定义”）
    curve: f32 = 0,       // 段曲率：-1..1（仅 smooth 有意义；0 = 线性）
};

const Lane = struct {
    target: Target,       // 见 §七（通道推子 / CC / BPM / …）
    interp: enum { hold, linear, smooth },
    points: ArrayList(Point),   // step 升序，≥ 1 点
    smoothing: f32 = 0,   // 播放侧一极点平滑（0 = 关；hold 模式建议开）
};
```

**四条铁律**

1. **只有这一套数据**：不存在“两种模式两套数据”，也就没有双向同步（两份真相 = 分叉 bug 的温床）。
2. **`hold` 段 ≡ “每格一个值”的数组**（数学上等价，不丢精度）——逐格模式就是一堆 `hold` 段。
3. **等值段自动合并**：相邻同值 + `hold` 合并为 2 个点（否则一次“画 16 小节恒定值”会生成上千点）。
4. **空 lane = 没自动化**：参数用 UI 上的静态值；空 lane 不写进存档。

## 三、两种编辑视图（切换零转换）

| 视图 | 用户看到 | 手势 → 底层动作 |
| --- | --- | --- |
| **柱条（逐格）** | 每格一根柱 / 一段台阶 | 拖一格 = 在该格边界放 `hold` 点，并与相邻等值段合并 |
| **包络** | 折线 + 可拖点 + 曲率手柄 | 双击线上加点、拖点、拖手柄调 `curve`、右键删点 |

- 切换**只换绘制与手势**，数据一个字节都不动；柱条视图在曲线段上显示“按格采样后的值”（预览，不改数据）。
- **混合编辑策略（默认 a）**：lane 里已有曲线段时，在柱条视图拖某一格 = 在该格前后插点、只把这一小段变 `hold`
  （“曲线里挖出一个台阶”），其他段不动。整条 lane 烘焙成逐格 = 独立命令（需确认、可撤销），**不做默认**。

## 四、求值（音频线程）

- 每 block 取首/尾 step → 定位所在段 → 按 `interp` 求值（`hold` = 段起点值；`linear` = 线性；`smooth` = 按 `curve` 造型）。
- 求值结果统一过**一极点平滑**（可复用 `audio.zig` 里音频片段增益的平滑代码），`smoothing = 0` 时不平滑（想要硬台阶的用户自选）。
- 参数投递路径：
  - 内置参数：写原子数组（`params.*`，已有机制）；
  - VSTi 参数：`IParamValueQueue`（可逐采样）或 CC 事件——两者都要“最后写入者胜”；
  - 事件型目标（如弯音/CC 给外部 MIDI）：走现有事件队列（`SchedEvent` 已有 `step`/`end_step` 语义，需扩一个参数事件类型）。
- **待定**：点数组的跨线程发布方式（双缓冲 + 版本号 vs 发布指针 + 原子序号）——先按“UI 线程构造新数组、音频线程按版本切换”设计。

## 五、存储与历史（字段纪律，一步都不能漏）

新字段必须一次改全**五处**，否则就是 `instrument_order` 那个坑的重演（改了不进历史 / 不标脏 / 撤销丢数据）：

1. `persist`：`automation: []SavedLane`，`binary_version` +1，`introducedVersion` 用固定版本号；
2. `captureHistory`：深拷贝 lane 点集；
3. `stateEqualsCurrent`：**比较 lane 内容**（否则改自动化不产生历史、不标脏）；
4. `applyHistoryState`：恢复（含 lane 数量/顺序，非法数据回落空）；
5. `freeHistoryState`：释放（否则每次提交泄漏）。

## 六、与 MIDI 的关系（烘焙只在出口）

- **导出**：lane → CC 事件，按 tick 采样；`interp = hold` 时只在“值变化处”发事件（事件数最省）。
  弯音 → Pitch Bend（14 bit）；通道声像 → CC10。
- **导入**：CC 事件 → lane（每个事件一点 + `hold`），round-trip 只保证“采样点一致”，不保证曲线形状。
- **内部永不量化**：量化只发生在这两个出口。

## 七、目标定义（target）与归属

`target` 必须是**稳定 id**（不是名字），否则改名/重载插件后 lane 对不上：

| 类别 | 示例 | 归属（lane 挂在谁身上） |
| --- | --- | --- |
| 全局 | 主音量、**BPM**、拍号 | 工程（单条） |
| 调音台通道 | 通道音量 / 声像 / 静音、效果器参数 | **通道**（不是轨道行！一个通道可能被多个乐器/轨道使用） |
| 乐器 / MIDI 通道 | CC 0–127、弯音、触后 | 乐器（本工程约定：一个乐器 ≈ 一个 MIDI 通道） |
| VSTi 参数 | 插件参数 id | 插件实例 + 参数 id |
| 音符属性 | 力度、音符声像 | 音符（**不是 lane**，保持现状） |

### 7.1 视图分工：两个编辑区，作用域互不交叉

| 编辑区 | 位置 | 可编辑的 target |
| --- | --- | --- |
| **钢琴窗下方编辑区**（由现有 `view_note_lane.zig` 改造） | 卷帘底部 | **乐器 / MIDI 通道级**：音符属性（力度、音符声像）+ 该乐器的 CC / 弯音 / 触后 |
| **播放列表自动化区**（新增，同款 UI） | 播放列表轨道区下方 | **全局 / 调音台级**：`通道 A · 音量`、`通道 A · 声像`、主音量、**BPM** 等 |

理由：

- 卷帘里能看到“音符与曲线的**时间对齐**”，所以乐器级的东西在卷帘里画；“这条自动化覆盖了哪几个片段”要在播放列表里才看得清，所以全局/调音台级的东西在播放列表里画。
- 两处**共用同一套 lane 渲染器与手势**（柱条/包络两个视图、加点拖点、值域映射、行高、颜色），但**数据源与 target 白名单不同**。
  实现上抽成“值轨控件”，输入 =（lane 列表, 值域, 颜色, 行高）。
- **不允许交叉**：卷帘里不能编「主音量」，播放列表里不能编某乐器的 CC。
  需要时用“跳转”而不是“复制”：参数旁的小圆点 → 跳到对应编辑区并高亮该 lane。
