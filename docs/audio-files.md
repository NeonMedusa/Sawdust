# 音频文件 / 采样器 — 设计（v1 定稿）

> 本文是 2026 年讨论定稿的设计基线。实现按 **P1 → P2 → P3** 推进；
> 未列进"v1 范围"的一律**不做**（见 §9 非目标），不要"顺手加"。

## 1. 目标

1. **音频文件进入工程**：WAV / FLAC / MP3 / OGG-Vorbis 可由用户加载、引用、播放；
2. **采样器鼓组层**：鼓垫的层可以是"真实采样"（一次性、原速）——层 = 乐器槽的
   既有架构直接支持（`docs/drumkit.md` §7 预留）；
3. **播放列表音频片段**：音频像样式片段一样可拖放/裁剪，波形入片段；
4. **单文件追求不变**：所有编解码编进 `Sawdust.exe`，不引入 DLL。

## 2. 编解码（调研定稿：零新依赖）

已 vendored 的 **miniaudio v0.11.25** 内置解码器（宏实测）：
`MA_HAS_WAV` / `MA_HAS_FLAC` / `MA_HAS_MP3` / `MA_HAS_VORBIS` ✓ —— 且
`miniaudio_impl.c` 无任何禁用宏 → **早已编进每个构建**（ReleaseFast ≈ 3.19MB 已含）。

| 格式 | 来源 | 许可 | 结论 |
|---|---|---|---|
| WAV / FLAC / MP3 / OGG-Vorbis | miniaudio 内置 | PD / MIT-0 | ✅ v1 |
| Opus | libopus+opusfile（BSD-3；源码编进 exe 或自定义后端） | BSD-3 | 以后 |
| AAC | faad2=GPL / FDK-AAC=专有条款 | ✗ | **放弃**（提示用户转码） |
| AIFF/CAF | miniaudio 无 | — | 跳过（以后可自写 PCM 解析） |

API 要点（`audio.zig` 已 `@cImport` miniaudio.h）：
- **`ma_decoder_init_file_w`（宽字符路径）必用**——中文路径老坑（见 `pitfalls.md`）；
- `ma_decoder_config_init(f32, 2, 0)` → **不重采样**（原生率直出）；播放侧靠 `SampleData.ratio`（原生/引擎）换算采样帧——导入更快，且改引擎采样率不再需要重解码；
- `ma_decoder_get_length_in_pcm_frames`（时长/波形）；`ma_data_converter_*` 留给流式（以后）。

文件拖入：窗口层补 `DragAcceptFiles` + `WM_DROPFILES`（尚未支持）；另有"浏览文件…"入口。

## 3. 资产层（AudioAsset）

```
AudioAsset = { 绝对路径（内存态）, 解码缓冲 f32@**原生采样率**（+ ratio）, 峰值缓存（min/max 分桶；与解码单遍、桶大时抽样）,
               引用计数 }
```

- 按路径去重；鼓采样与音频片段**共用**同一资产；
- v1 **整文件解码进内存**（鼓采样毫秒级；长音频设上限 + 提示；流式播放以后）；
- 释放：引用计数归零 + 帧末回收（沿用退役链纪律）。

## 4. 音频样式（AudioStyle）——片段共享的"内容"

**与音符样式对称**（样式 = 内容、片段 = 摆放）：

```
AudioStyle = { 编号, 名称, 来源资产, 混音通道, 增益 }
```

- **推子/通道 = 样式级**（用户拍板 2026-10）：双击窗口里的通道/增益调整作用于
  该样式的**所有片段实例**（窗口内标注"此采样全部实例共用"）；
- **片段级增益 v1 不做**（以后"真的"有需求再加）；
- 拖入同一文件第二次 → **按路径复用已有音频样式**（同"点样式"直觉）；
- 混音台只多"一个音频源一个通道条目"，不因实例数膨胀。

## 5. 音频片段（AudioClip）

```
AudioClip = { 轨道, 时间轴起止（步）, 采样内起点/终点（帧 trim）, 引用 AudioStyle }
```

- 拖动/裁剪/层级/沉底与现有片段同手感（复用 `topmostClipAt`/沉底等机制，
  按片段种类分派）；**双击 = 打开音频窗口**（样式片段双击仍是钢琴卷帘）；
- 一段音频被裁成多段（不同 trim）时各成一片段、共享样式推子。

## 6. 播放模型（音频线程）

- **不走调度事件**：音频线程**每块"活动片段扫描"**——按当前传输位置判断哪些
  片段应在响：进入 → 起播（含采样内偏移）、离开 → 停、跳转/循环 → 按新位置
  重算偏移重启（天然支持跳转/撤销/循环，不动调度器）；
- v1 **原生速率、无时间拉伸**；片段长度与音频时长独立（截断播放）；
- 混入**样式的混音通道**（与乐器同一条通道链：EQ/效果/推子照常）；
- 每片段一行发布到音频线程（片段索引 → 通道/增益/采样指针/trim）——**只增不减**
  的容量纪律同池化层（`docs/resources.md`）。

## 7. 窗口（两个入口，同一实现）

一个"波形编辑器面板"，两种挂载：

| 入口 | 内容 |
|---|---|
| **音频片段窗口**（双击音频片段） | 波形（本片段 trim 段高亮）+ 起点/终点手柄 + 试听（游标/播放/暂停）+ **样式级**通道/增益 |
| **采样器层窗口**（鼓垫层行 [编辑]，`LayerKind.sampler`） | 波形成员 + 同款试听/trim + 根音（=垫音高）/一次性/层增益 |

- **试听 = 局部预览**：独立于主传输（不动主播放游标）；走各自通道
  （片段走样式通道、鼓层走鼓组乐器通道）——用户拍板 ✓；
- v1 **不做波形缩放**（先原型看手感，之后再议——钢琴窗同款 Ctrl+滚轮手势可复用）；
- 波形峰值：资产层加载时算好分桶 min/max，按像素宽取样绘制。

## 8. 采样器（鼓组层）

- `LayerKind += sampler`（一次性 one-shot，v1）；
- 层字段：来源资产、采样内起止、增益（已有 `gain`）；
- 播放：**原速一次性**（垫音高不改变速度；"跟随音高变调"是另一个设计，
  用户明确 v1 不做）；复用层 = 乐器槽的整套基建（事件按音高分发 ✓ 已现成）；
- 采样器层的试听由采样器窗口负责（同 §7 面板）。

## 9. 非目标（v1 明确不做）

变速/变调播放、时间拉伸、流式播放、波形缩放、片段级增益、AAC、Opus、
音频内嵌进工程、AIFF/CAF、采样循环/门限模式、多采样力度分层、round-robin。

## 10. 存档

- 新表：**资产引用**（按**相对路径**存，工程文件夹便携）+ **音频样式表**
  （名称/通道/增益/资产引用）+ 音频片段字段（样式号/时间轴/trim）；
- **不内嵌音频**（用户拍板）；缺失文件 → 保留引用、静音、片段/窗口标红提示，
  文件恢复后自动重载（同"插件自愈"惯例）；
- v5 二进制与 JSON 两条通道同步（反射编码覆盖新结构；格式未发布 → 零迁移义务）。

## 12. 测试清单（实现时逐条落）

- 解码：各格式夹具 → 帧数/采样率/峰值合理；中文路径；缺失文件静音；
- 资产：去重、引用计数、释放无泄漏（testing allocator）；
- 采样器层：事件按音高分发、原速一次性、增益、存档往返、撤销；
- 音频片段：放置/拖动/trim、跳转/循环重启正确（样本偏移）、样式推子全实例共享、
  存档往返（相对路径）、撤销/重做；
- 窗口：试听不扰动主传输、trim 手柄边界钳制。

## 8. 导入性能路线图（P1/P2/P3）

> 记录于实测"拖入音频整程序卡死"之后。P1 已落地；P2/P3 待排期。

### P1（已完成）：解码提速
- **不重采样**：`ma_decoder_config_init(f32, 2, 0)` 原生率直出；`SampleData.ratio`
  （原生/引擎）+ `engFrames()`；引擎侧取样本处乘 ratio（片段扫描/试听/采样器声部），
  UI 与 trim 仍为引擎帧域。改引擎采样率不再需要重解码。
- **峰值与解码单遍**：桶 > 32 帧时按 `bucket/16` 步长抽样（只影响显示精度）。
- 效果：省掉整遍 SRC 与整遍峰值遍历；**窗口仍会阻塞**（解码本身还在 UI 线程）。

### P2（待排期）：两阶段异步导入（真正消除冻结）
**目标**：拖入即见片段（按文件头时长给出正确长度），加载完成后自动填充。
1. **阶段 A（毫秒级，UI 线程）**：`ma_decoder_init_file_w` + `get_length_in_pcm_frames`
   只读文件头拿时长 → 立即建样式 + 片段（长度 = 时长 × BPM × 每拍步数），片段标注
   "加载中…"（斜纹占位波形 + 进度百分比）；**顺手把最终缓冲一次性分配好**（帧数已
   知——这是"所有权不跨线程"的关键）。
2. **阶段 B（工作线程）**：`std.Thread.spawn` 解码进阶段 A 的缓冲 + 算峰值；不断更新
   `done_frames` 原子量。worker **只写自己那块内存**，不碰 App、不分配、不 free。
3. **阶段 C（回到 UI 线程）**：每帧检查 `done/failed/cancel` 原子量 → 完成后把缓冲
   过继给资产池并设置 `style.asset`；播放表**每帧重算 + 逐字段比对**，下一帧自动出声
   （无需额外通知逻辑）。
- 边界：取消（删片段/关工程 → `cancel` 原子量；确认线程结束后再释放缓冲）、失败
  toast、多文件拖入用 job 队列顺序执行、进度条读 `done/total`。
- 测试：用现成的生成 WAV 跑完整流程（占位 → job 完成 → 播放表出现该行）。

### P3（可选）：长文件与内存
- 流式读取（只保留用得到的区段；v1 是整文件进内存，上限 30 分钟）；
- 峰值懒计算 / 逐级细化（先粗后细，滚动时补算）；
- 若将来需要"片段级增益/淡入淡出"，与导入管线解耦单独做。
