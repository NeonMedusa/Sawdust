# 音频输出与离线导出

> 一句话：输出设备在启动时从 miniaudio 枚举并按保存的名称选中（**运行时也可热切换，
> 仅后端切换需重启**）；离线渲染始终先写 24-bit WAV，压缩格式在渲染完成后交给 FFmpeg 编码。

## 核心模型

### 输出设备

`audio_pref.zig` 保存两项：后端（自动 / PulseAudio / ALSA / JACK）与播放设备名称。
名称而非 `ma_device_id` 是持久化键：后者是后端私有二进制联合体，驱动更新、重插设备
和重启后都不保证稳定。

启动时 `audio.Engine.init()` 必定建立 `ma_context`，枚举播放设备并复制名称和临时 ID：

1. 偏好为空 → `pDeviceID = null`，miniaudio 选该后端的系统默认设备；
2. 找到同名设备 → 用本次 context 枚举到的 ID 初始化；
3. 找不到 → 记录诊断并安全回退系统默认。

**设备切换立即生效**（同一后端内）：`Engine.switchPlaybackDevice(name)` 会停掉旧
`ma_device` → 用新 `pDeviceID` 重建 → 启动，**锁定当前采样率**（`config.sampleRate =
当前值`，由后端重采样）——这样插件实例、效果器缓冲、帧↔步换算全部不用重建。
切换失败（设备被占、不支持当前采样率、启动失败）会**自动回滚到原设备**并弹提示；
新设备给不出同一采样率时**不会默默换**（音高/速度会整体跑偏）。
导出进行中不切（设备已被独占停用），`pending` 保留到导出结束。

**后端切换仍需重启**：换后端 = 重建 `ma_context`，影响面比设备大得多，暂不做热切换。
设备列表在**打开设置页时重新枚举**（运行中新插的设备能立刻看到）。

### 导出

离线导出沿用 `audio.renderBlock()`，所以实时与离线的合成、调音台和插件路径一致。
WAV 直接写目标；MP3/FLAC/OGG 先写同目录的
`<目标>.sawdust-render.tmp.wav`，再以无 shell 的 argv 调用 FFmpeg：

| 格式 | 质量参数 | FFmpeg 参数 |
|---|---|---|
| WAV | 固定 24-bit PCM | 不需要 FFmpeg |
| MP3 | 128 / 192 / 256 / 320 kbps | `libmp3lame -b:a` |
| FLAC | 0 / 5 / 8 / 12 | `flac -compression_level` |
| OGG Vorbis | 128 / 192 / 256 / 320 kbps | `libvorbis -b:a` |
| Opus | 128 / 192 / 256 / 320 kbps | `libopus -b:a` |

文件扩展名由格式选择决定：保存框里手打了不匹配的扩展名时会被替换，避免容器和后缀
不一致。压缩格式需要 `ffmpeg` 在 `PATH` 上；**打开导出面板时会重新探测一次**
（`ffmpeg -version`，热 53ms / 冷 171ms），缺失时 MP3/FLAC/OGG/Opus 按钮**置灰不可点**、
当前选择自动回退到 WAV；**点一下置灰的按钮也会重测**——运行期用 scoop/winget 装好即可用，
不必重启（但 `PATH` 是启动时快照：若 ffmpeg 装到了**新目录**，仍需重启软件）。
真正编码失败时保留渲好的 WAV 并显示可操作的原因（见下）。

### 导出日志（`SAWDUST_EXPORT_LOG`）

默认**不写** `.log`（早先的排障产物，不该往用户目录里丢）。需要现场排障时
以 `SAWDUST_EXPORT_LOG=1` 启动，成功导出会在目标旁边生成 `<目标>.log`，
记录每 32 块的帧数/事件/峰值等诊断字段。

### 编码失败时的行为

WAV 渲染完成、只是最后的 FFmpeg 编码失败时：**保留整整渲好的 WAV**（不删），
目标文件/半成品删掉，提示里给出保留路径，例如
「未找到 FFmpeg（请安装并加入 PATH，或改用 WAV 导出）；渲染好的 WAV 已保留：…」。
渲染本身失败（磁盘满/写入错误）时仍然删半成品。

## 手势与状态

1. 文件 → 导出音频：先弹格式/质量面板；
2. 选格式、码率或 FLAC 压缩等级后，点“选择位置并导出”；
3. 保存框只收集路径；随后进入现有的进度/取消对话框；
4. Esc 在格式面板中关闭面板，在渲染进度中请求取消。

设置 → 音频输出中，“系统默认”永远是列表首行；其它设备按当前启动后端的枚举结果
展示。设备多时列表独立滚动，不截断设备集合。

## 不变量

- 音频回调内不枚举设备、不分配、不执行 FFmpeg；
- 导出期间设备保持暂停，结束、取消、失败均恢复传输快照、插件状态和设备；
- 压缩格式的临时 WAV 只在最终编码成功后删除；取消/失败删除临时文件和可能的半成品；
- 已保存但暂时不存在的设备绝不能让应用无声启动失败，必须回退系统默认；
- 输出设备名称只在本次 context 的枚举 ID 有效期内映射，绝不持久化 ID。

## 调用方契约

- `audio_pref.load()` 必须早于 `Engine.init()`；设置页只调用 `requestBackend` /
  `requestDevice`，由主循环帧末落盘；
- 调用 `App.exportAudioBegin()` 的路径必须来自 `audio_export.targetPath()`，以保证扩展
  名与编码格式一致；
- 发布版本若要承诺“零外部依赖的 MP3/FLAC/OGG”，必须替换 FFmpeg 适配层为随程序分发
  的编码器，并重新核对相应许可证；当前实现明确依赖用户系统的 FFmpeg。

## 测试清单

- `audio_pref`：旧版仅后端数字配置可读；新版设备名配置可读；
- `audio_export`：格式扩展名、扩展名替换；有 FFmpeg 时实际生成 MP3 / FLAC / OGG；
- 手测：选择非默认输出设备后重启，确认 `Engine` 使用该设备；拔掉已保存设备后重启，
  确认回退系统默认；
- 手测：四种格式分别导出，检查播放器可打开、码率/FLAC 等级符合选择，并在 FFmpeg
  不存在时确认不会残留 `.tmp.wav` 或空目标文件。
