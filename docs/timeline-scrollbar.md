# 横向时间轴滚动条（minimap 语义）——设计文档

> 实现：`src/ui.zig` 的 `scrollbarTimeline` / `scrollbarTimelineEx`
> 调用方：`src/view_playlist.zig`（id 8）、`src/view_pianoroll.zig`（id 10）
> 测试：`src/ui_test.zig`（7 个专项测试）

## 一句话概括（用户视角）

> 这个滚动条不是普通滚动条：**滑块表示当前视图在整条时间轴上的位置和范围**。
> 拖滑块中间 = 平移视图；把滑块拖到端点后**继续拖** = 把时间轴往那个方向
> 延长（或缩短），滑块随之变短（或变长）；拖滑块的左/右边缘 = 缩放视图
> （视野变宽/变窄），像拉伸一个窗口。

## 核心模型

**滑块 = 视口在时间轴上的投影**（而不是一个抽象的"滚动位置手柄"）：

```
时间轴（content_w，内容像素）
├────────────────────────────────────────────────────────────┤
│                    ┌──────────┐                            │
│                    │  滑块     │  ← 滑块左缘 = 视口左缘      │
│                    │ (thumb)  │     滑块右缘 = 视口右缘      │
│                    └──────────┘                            │
│                    └── view_cw ──┘                         │
```

拖动滑块 = **直接操作视口本身**（移动它、拉伸它），而不是"滚动一个位置"。

### 坐标系与变量

| 变量 | 含义 | 单位 |
|---|---|---|
| `content_w` | 时间轴总长（**动态**：内容右缘 + 留白，可被用户拖长） | 内容像素 |
| `scroll` | 视口左缘在时间轴上的位置 | 内容像素 |
| `zoom` | 屏幕像素 / 内容像素（横向缩放） | f32 |
| `view_w` | 视口屏幕宽度（调用方传入） | 屏幕像素 |
| `view_cw` | 视口可见内容宽度 = `view_w / zoom` | 内容像素 |

### 滑块几何（不变量）

```
thumb_w = clamp(view_cw / content_w × w, [min_w, w])     // min_w = 轨道高（正方形下限）
thumb_x = x + (scroll / max_scroll) × (w - thumb_w)      // max_scroll = content_w - view_cw
```

即：**滑块宽 ∝ 视口占时间轴的比例**；滑块位置 ∝ 视口在时间轴上的进度。
注意这是**比例映射**（thumb 行程 `w - thumb_w` ↔ scroll 范围 `content_w - view_cw`），
不是 1:1 屏幕映射。

## 三种手势

### 1. 拖主体（平移，标准拖动）

鼠标抓在滑块内（离两缘 > `edge_zone`）→ 滑块 1:1 跟手：

```zig
ns = clamp((desired - x) × max_scroll0 / travel0, 0, max_scroll0)
```

`max_scroll0`/`travel0` 取自**按下时快照**（见"快照语义"）。

### 2. 拖主体越过端点（延长 / 回缩时间轴）——本控件的特色

滑块已经贴右端，**继续往右拖**：此时抓的不是"位置"而是**滑块左缘**——

- 滑块左缘 1:1 跟随鼠标，**右缘钉在轨道右端**（滑块被压缩变短）；
- 由滑块宽反推时间轴长：`content_w = view_cw × w / thumb_w`；
- 视口贴到新的右端（`scroll = content_w - view_cw`）。

```
拖前：├────────[滑块]│           （滑块贴右端）
继续右拖：  ├────────[滑块]──→   （左缘跟手、右缘钉住、滑块变短）
结果：时间轴变长、滑块变短 = 右边多出一段可用行程
```

贴左端继续往左拖则相反（滑块右缘跟手、左缘钉住 → 时间轴回缩、scroll 归 0）。

**为什么这样设计**：不需要全局设置"时间轴要多长"——用户在任何时刻
发现右边不够用，拖一下就有更多空间；滑块变短本身就是"时间轴变长"的反馈。

### 3. 拖边缘（缩放视图）

`edge_zone = min(8px, max(4px, thumb_w/3))` 内按下 → 缩放：

| 手势 | 钉住 | 效果 |
|---|---|---|
| 拖**左缘** | 滑块右缘（= 视口右缘的内容位置） | 左缘左移 = 视野变宽（zoom 变小）；右移 = 视野变窄 |
| 拖**右缘** | 滑块左缘（= 视口左缘的内容位置） | 右缘右移 = 视野变宽；左移 = 视野变窄 |

窄滑块两缘都在 8px 内时，按鼠标离哪边更近决定（`on_left and on_right` 分支）。

## 每帧规范化（钳制）——"状态卫生"

控件每帧开头对三个变量做规范化（无论是否在拖动）：

```zig
// 1) zoom 只钳上限，不被动抬高
if (zoom < 0.001) zoom = 0.001;
if (zoom > zoom_max) zoom = zoom_max;
//    ↑ 内容缩短时调用方的 zoom_min 会变大——若每帧强制命中，视口会被
//      自动放大、右缘回缩（实测困扰）。缩放下限只在"用户主动缩放"时生效。

// 2) content_w ∈ [lo, square_limit]
lo = max(content_min_w, view_cw);           // 下限：贴合内容（且不短于一屏）
square_limit = max(lo, view_cw × w / min_w); // 上限：滑块缩到正方形为止

// 3) scroll ∈ [0, content_w - view_cw]
```

### 延长行程的"保留 / 回收"规则

- **拖出的延长保留**（松手不回弹）——用户拖出来的工作区不该消失；
- **回到左端时**（`scroll == 0` 且不在拖动中）→ `content_w = lo`（回收延长）——
  用户回到起点 = "收工"，时间轴重新贴合内容，避免陈旧膨胀。

## 缩放下限：必须含"物理下限"（拖不动事故的修复）

拖边缘的 zoom 下限：

```zig
zoom_floor = min(zoom.*, min(zoom_min, view_w / content_w));
```

- `zoom_min`（调用方给的动态下限）锚在**内容右缘 + 留白**（timeline_w）上；
- `view_w / content_w` 是**物理下限**：视野最多扩到"装下全部内容"（此时滑块满宽）；
- **取更松的那个**（min）：拖出的延长让 `content_w > timeline_w` 时，
  物理下限比 zoom_min 更松——若只用 `min(zoom_min, zoom.*)`，
  当 zoom 已低于 zoom_min（初始 1.0、时间轴短于视口）时下限 = zoom →
  **拖左缘被钳死、拖不动**（实测 bug：滑块左边空一段可用行程却拉不动）。

> 教训（已收入 `pitfalls.md`）：多个"下限"取**最松的那个**；参数约束若比
> 物理约束更严，说明它漏了场景。

## 快照语义（拖动全程按"按下时"换算）

按下瞬间快照进 `Ui` 的拖动字段，**拖动全程只用快照**：

| 字段 | 内容 | 谁用 |
|---|---|---|
| `drag_content0` / `drag_view_cw0` | 时间轴长 / 视口宽 | 主体拖动（反推换算） |
| `drag_scroll0` | 视口位置 | 缩放（内容位置守恒） |
| `drag_start` | 鼠标在滑块内的抓取偏移 | 全部手势 |
| `drag_anchor_x` | 钉住的边缘（屏幕 x） | 拖边缘缩放 |
| `drag_mode_h` | `.body` / `.left` / `.right` | 分支 |

**为什么必须快照**：拖动中滑块宽度会变——若每帧用当前值重算换算基准，
会产生正反馈（滑块缩→基准变→滑块缩更快 = 加速/漂移）。
这与其他拖动控件（推子/音符拉伸）是同一原则。

## 视觉设计

- **滑块半透明**（拖动 a=150 / 悬停 a=120 / 静止 a=70），minimap 内容块
  （片段/音符分布）从滑块下透出——滑块同时是"视口投影"的可视化；
- 静止时用偏白色（`scrollbar_light`）保证压在 minimap 上仍可见；
- 悬停/拖动时用 accent 色 + 边缘光标变 `resize_h`（缩放提示）。

## 调用方契约（新视图接入时照抄）

```zig
// 1) 时间轴长度（内容右缘 + 右侧留白，保底若干小节）——**同一个值**既作
//    content_min_w 又作滚轮缩放的 content_span：
timeline_w = (bars_right + 3) × bar_w;      // 保底 4 小节 + 3 小节留白
// 2) 动态缩放下限：视图恰好容纳整个时间轴 → 缩到底时滑块满宽（无假行程）
dyn_zoom_min = min(8.0, view_w / timeline_w);
// 3) 调用（mini 块可选：播放列表 = 片段、钢琴卷帘 = 音符）：
_ = ui.scrollbarTimelineEx(id, x, y, w, h,
    &scroll_x, &content_w, &zoom, view_w, timeline_w, dyn_zoom_min, 8.0, mini);
```

**id 约定**：播放列表 8、钢琴卷帘 10（各视图的交互 id 段见 `ui.zig` 注释）。

## 相关交互（配套，不在本控件内）

- **Ctrl+滚轮缩放**（视图侧）：鼠标锚定（`Ui.zoomAnchoredScrollX`）+
  **无条件拉回**（`Ui.clampScrollToSpan`）——视口右缘不越过内容跨度
  （留白区只留 3 小节用量），缩到极限自动贴左。
  与滚动条拖动的区别：拖动可以留在延长区（直接操作），滚轮缩放会拉回（内容聚焦）。
- **□ 缺口**（`Ui.zoomSquare`）：拖轨道行高 / 音高行高。
- **垂直滚动条**（`Ui.scrollbarV`）：标准滚动条，无 minimap 语义。

## 附：如何向人描述这个控件（自然语言模板）

> 这是个"视图投影"滚动条：滑块就是你当前看到的时间窗口。拖它移动窗口；
> 拖到尽头继续拖，时间轴会朝那个方向变长，滑块变短、右边空出行程；
> 拖它的左右边缘是拉伸/压缩窗口（缩放）；所有拖出的延长在你回到最左端时自动收回。
